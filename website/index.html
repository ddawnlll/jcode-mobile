01 / Premise Server → phone

The work runs on your server. The phone is how you return.

Adapter v2 is one Rust process beside JCode. It speaks to the curated SDK and harness API, keeps one SQLite journal, and exposes an authenticated mobile WebSocket. It does not run a second agent or proxy a provider key.

Navigation, backgrounding, socket close, and force-quit are not cancellation. The adapter keeps the operation journal. When you reopen, the client reconciles the same server and the same session, or shows an honest recovery state.

02 / Continuity

Your phone can leave.
The work does not.

Three states from the real v0.3.0 stack. They show what the adapter and client preserve when attention stops.

Real captures. Isolated adapter.

Staged → Reserved → Dispatching → Accepted

Four states, not one spinner.

The composer does not blur writing, acceptance, and ambiguity. A lost write becomes an explicit unknown state. It is never resent automatically.

  • Draft saved locally, scoped to the server and session.
  • Accepted only after authoritative JCode evidence.
  • Stop is explicit. Navigation is not cancel.

Session scope / epoch + seq

The phone can go dark.

JCode keeps the turn. Events carry a session scope, an adapter epoch, and a monotonic sequence. A slow answer cannot overwrite newer work.

  • The daemon owns execution, history, and the live runtime.
  • Cached content paints first and is labelled as saved.
  • A gap forces a snapshot, not a guessed patch.

Exact server + session / reconcile

Return to the same thread.

Reopening restores the exact server and session. If the target is gone, the app shows a recovery state instead of creating a replacement.

  • Reading anchor and draft are restored in scope.
  • Plan, context, and activity stay source-backed.
  • Missing data stays unknown. It is not zero.

05 / Setup Server first

Three moves. One server.

The phone cannot start work on its own. You need a reachable JCode daemon on a Linux server, Adapter v2, and TLS for any remote connection.

Prerequisite / JCode pinned fork + Rust + TLS

  1. 01

    Build and run Adapter v2.

    One Rust binary speaks the mobile WebSocket and the JCode SDK. It does not run a second agent.

    cargo build --release -p adapter-server --bin jcode-adapter-v2

JCODE_ADAPTER_ALLOWED_ROOTS="$HOME/src" \
JCODE_ADAPTER_BIND=127.0.0.1:7646 \
./target/release/jcode-adapter-v2

    Put a TLS reverse proxy in front of the adapter. Never expose plain ws:// to the internet.

  2. 02

    Read the pairing code.

    The adapter prints a single-use code for this run. It expires after ten minutes and is exchanged once for a device token.

    Pairing code (valid for 10 minutes, single use):
ABCD-EFGH-JKLM

    `jcode pair` is the 0.2.x path. Adapter v2 generates and hashes its own code.

  3. 03

    Install and pair the phone.

    Install the Android APK, allow sideloading, then enter the TLS hostname and the code. The token goes into Android Keystore or Linux Secret Service.

    adb install -r jcode-mobile-0.3.0-android-release.apk
