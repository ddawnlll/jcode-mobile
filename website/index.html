01 / Premise Server → phone

The work runs on your server. The phone is how you check in.

JCode Mobile does not run a second agent, a shadow transcript, or a cloud relay. It attaches to the JCode daemon you already run. Continuation is set during attach, not in a final goodbye frame.

When the screen goes dark, the daemon does not read that as cancel. When you reopen, the app reconciles the same server and the same session. If the target is missing, it says so instead of quietly creating a replacement.

02 / Continuity

Your phone can leave.
The work does not.

Three illustrative states, built from real v0.2.0 captures. They show what the app preserves when attention stops.

Illustrative states. Not a live connection.

Draft saved → Sending → Sent to server → Accepted

Four states, not one spinner.

The composer does not blur sending, sent, and accepted into one spinner. A lost write becomes Delivery unconfirmed. It is never resent automatically.

  • Draft saved locally, scoped to the server and session.
  • Sent to the adapter, then accepted by the agent.
  • Stop is explicit. Navigation, backgrounding, and socket close are not cancel.

Attach / continue_on_disconnect = true

The phone can go dark.

The session stays attached to the daemon with continuation set during attach. Work keeps recording while the phone is away, including tools and plan changes.

  • The daemon owns execution, history, and the live session runtime.
  • Cached history returns first and is labelled as saved on this phone.
  • Daemon death is not treated as phone absence. The app shows a source-backed interruption.

Exact server + session / reconcile

Return to the same thread.

Reopening restores the exact server and session. If that target is gone, the app shows an honest recovery state and never invents a replacement session.

  • Reading anchor and draft are restored in scope.
  • Work and plan inspectors reflect the same session.
  • The return seam marks only what was actually recorded while you were away.

07 / Setup Server first

Three moves. One server.

The phone cannot start work on its own. You need a reachable JCode daemon on a Linux server, the mobile adapter, and TLS for any remote connection.

Prerequisite / JCode 0.99.1 or newer + Linux + TLS

  1. 01

    Run JCode and the adapter.

    The adapter speaks WebSocket to the phone and the daemon's Unix socket to JCode. It does not run a second agent.

    JCODE_ADAPTER_HOST=127.0.0.1 \
JCODE_ADAPTER_PORT=7644 \
bun integration/jcode-adapter/src/main.ts

    Put a TLS reverse proxy in front of the adapter. Never expose plain ws:// to the internet.

  2. 02

    Mint a pairing code.

    Run this as the same user that owns JCODE_HOME. The six-digit code is valid for five minutes and is exchanged once for a device token.

    jcode pair

    If the command is missing, check jcode --version and upgrade JCode.

  3. 03

    Install and pair the phone.

    Install the Android APK, allow sideloading for your file manager, then enter host:port and the code. iOS needs a Simulator build or your own dev build.

    adb install -r jcode-mobile-0.2.0-android-release.apk

    Read the full setup and TLS notes
